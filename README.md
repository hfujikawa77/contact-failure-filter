# 接触不良動画フィルター

[claude-famicom-emu](https://github.com/goroman/cluade-famicom-emu) のファミコン端子接触不良シミュレータのロジック(傾き→接触品質カーブ、アドレス/データ線のマスク処理)を、カメラ／動画映像に応用した実験。

## 起動方法

`type="module"` を使っているため `file://` で直接開くとCORSエラーになる。ローカルサーバー経由で開くこと。

```sh
cd /home/ardupilot/GitHub/contact-failure-filter
python3 -m http.server 8934
```

ブラウザで http://localhost:8934/ を開く。

- 「📷 カメラ映像」でWebカメラ、「📁 動画/画像を開く」でファイルを入力にできる。
- 「カセットの傾き」スライダー(±6°)で接触不良の度合いを調整。
- ADDR/DATA のピングリッドをクリックすると個別ピンを強制的にOFFにできる。
- 「💨 息を吹く」「🔌 挿し直す」は元のシミュレータと同じ挙動(息:65%の確率で復活/10%の確率で壊れる、挿し直す:全復旧)。

## ファイル構成

- `bus.js` — 60ピンコネクタの接触品質モデル(元プロジェクトの `contactQuality`/`applyContacts` を移植)。
- `glitch.js` — アドレス/データマスクを映像フレームに適用する処理本体。
- `app.js` — カメラ/ファイル入力とUIの配線、描画ループ。
- `index.html` / `style.css` — 画面。

## 現状のメモ

映像フレームをそのままRGBとして扱ってマスクをかけていた最初のバージョンは、粗いブロック状/帯状の崩れにしかならなかった。そこで、映像を一度NESのCHRデータと同じ2bpp形式(1タイル=8x8、プレーンごとに8バイト、1バイトが1行分8ピクセルのビット列)にエンコードしてから同じアドレス/データマスク処理をかける方式に変更(`glitch.js`)。1バイトの化けがタイル1行=8ピクセル分のビットとして効くようになり、目的の細かい縦縞ノイズにかなり近づいた(`tilt` を -1.5°〜-3° あたりにすると分かりやすい)。

既知の癖:

- 実装しているのはPPU側のアドレス/データピン(A0-A13, D0-D7)のみで、これらは接続端子の右寄りの列に集まっているため、**傾きがマイナス側のときだけ**崩れが目立つ(プラス側はほぼ無傷)。実機の全ピンをカバーしていない簡易版であることによる非対称性。
- データピンが全滅する角度まで傾けると、バスの値が1点に固定されて画面が単色でフリーズする(オープンバスが動かなくなるため)。これは実機の重度の接触不良に近い挙動ではあるが、見た目としては面白くない。
